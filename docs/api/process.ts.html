process.ts

The process host module: the environment, script args, working directory, exit, and stdio of the running process, as an import rather than a global.

process deliberately shares a name with Node's global, so an importer's bare process means this module, and the export shadows the global only where it's imported. The runtime has no global at all, so a module that reaches the process shows it in its imports.

An Env is read-only and holds a snapshot taken when this module loads, the runtime's fixed environment: a write to the global's process.env afterward changes nothing here, and only names listed by env.narrow reach a narrowed handle. A name outside its set throws not_granted, so a denial is never read as a variable that's unset, which is undefined from get. Library edges take plain records, built at a root from get_all. An environment value can be a secret: this module prints none, its errors naming the variable, never the value, so what a value becomes after a read is up to the caller.

args are the arguments after the script, a frozen array, what a script given to gro run receives and what a bare node script.ts receives. In the CLI's own process they're the CLI's args, the task name included, since a task's parsed args are on its context.

Handles and their prototypes are frozen, null-prototype so none of them is thenable even with a polluted Object.prototype.then, and constructing one takes a key only this module holds. A method called on any other object throws TypeError, private fields being the only state. args is no handle but a real array, frozen, so its prototype is the unfrozen Array.prototype and awaiting it adopts a polluted then.

This is the Node implementation, which runs on the Node Gro. Its gaps against the runtime's builtin, which it documents rather than the API weakening to match:

  • The global process stays, and any module can read process.env or call process.exit, so a narrowed Env bounds only code that uses it, a review signal, not a boundary.
  • The root Env allows every name, where the runtime's holds only the granted ones and a name outside them throws not_granted.
  • The snapshot is taken at this module's load, so a write to process.env before that shows.
  • args under node -e and node -p reads the undocumented process._eval, as no documented API says the process has no script.
  • exit in a Node worker ends the thread, not the process.
  • On POSIX Node's stdio writes to files and terminals block the event loop until the kernel takes them, where the runtime's complete on its own schedule. Writes to pipes are asynchronous.
  • Intrinsics stay pollutable. The Node functions this module calls are copied at load, but Node's stream write is the stream's own, so code that patched it runs inside a write, and the streams are created on first use, so one replaced on the global by then is the one written to. The stream classes and EventEmitter.prototype (once, emit, listenerCount) stay too, so code that patches them runs inside these ops holding the raw stream.
  • A chunk read from stdin passes through Node's iterator, so a polluted then can replace it.
  • Importing this module throws in a removed or non-UTF-8 working directory, as fs does.
