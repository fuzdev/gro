spawn.ts

The spawn host module: starting programs through handles pinned to one executable.

A SpawnProgram is the capability to run one executable, the shape a spawn grant takes on the runtime. spawn.program('git') resolves the name once, synchronously, walking the host's PATH: only absolute entries, the first regular executable. The real path is pinned for the handle's life, so a later PATH change never changes which binary runs. The walk skips every entry spelled as a node_modules/.bin directory, which npm run and deno task put ahead of the rest, so a dependency's bin in one can't shadow git, and a project's tools are reached only by a name containing /. A name containing / resolves against the project root instead, and one that's absolute or climbs above the project through .. is not_granted, a check of the name as written, since a symlink beneath the project can lead anywhere. A native binary runs at its pinned real path. A bare name is its own argv[0], because a multicall binary (~/.cargo/bin/cargo -> rustup) dispatches on it, and a name containing / passes its lexical project-absolute path, so a tool that finds itself through argv[0] (a virtualenv's python) still does under another cwd. A #! script runs at the path it was found at, the PATH entry's or the lexical project-absolute one, symlinks included, since the kernel hands its interpreter that path as $0 in place of argv[0], and a script that dispatches on the name it was called through (Debian's psql, a link to pg_wrapper) needs it. A script is pinned by identity, the device and inode of the descriptor its first bytes were read from, and each launch stats the found path again and refuses it, launch_failed, when it leads to another file: a link retargeted, or a file renamed over the pin. The same file reached by a new real path, a directory above it moved and linked back, still runs, and a script rewritten in place, or deleted and recreated on a reused inode, still matches. The check comes before the exec, and the interpreter opens $0 by path after it, so a link retargeted before the interpreter opens the script runs what it then leads to. In that window, whoever can write a directory on the found path can redirect a held handle, where a native binary is reached only through its pin's own path. A native binary runs at its pin, unchecked. A file this user can't read can't be told apart, so it's taken as native: an unreadable script pins, and fails at each call when its interpreter can't open it.

A call is argv only, never a shell string, its name and arguments checked strings. A file is pinned only when its first bytes are #! or the native binary magic of the host's platform, Mach-O on macOS and ELF elsewhere, since on Linux execvp, which Node's child start uses, hands any other file the kernel won't run to /bin/sh. A file with execute permission this user can't read passes, as it can't be inspected, and binfmt_misc formats are refused. .bat and .cmd are refused, as what cmd.exe would interpret. A non-zero exit is a result; SpawnError (spawn_error.ts) means a program couldn't be found or started, a call whose signal had already aborted included, which starts nothing. Handles come only from this module, hold their pin, the path they run at, argv[0], and environment in private fields, and are frozen with their prototypes, so a method called on any other object throws TypeError. spawn.narrow(names) keeps only named programs, and narrowing can only shrink. A narrowed root refuses env, which turns a named program into arbitrary execution (LD_PRELOAD), and pass_env: 'all' and pass_env globs, so a holder of a narrowed root can't take the whole environment. Named pass_env stays, forwarding one host value at a time. To give a library a program with an environment, build the SpawnProgram at the root and hand that down.

spawn.program_in(dir, name) resolves name beneath the directory of an fs handle instead, for a program a run builds outside the project, by the rules dir resolves any path with: an absolute name, a .. above dir, an absolute symlink, or a relative one that climbs out is not_granted, and a relative symlink that stays inside is followed. The name is pinned as a name containing / is, its argv[0] and a script's $0 the path it was found at, absolute. dir must be a handle this copy of fs made, checked through a registry that links no fs (internal/fs_handles.ts), so a forged object is a TypeError. A narrowed root refuses program_in and find_in, as a set of names can't grant a directory. To let a library run what it builds, bind the directory at the root: (name) => spawn.program_in(cache, name).

A child's environment is cleared, the rules of the runtime's grant: PATH, HOME, TMPDIR, and TERM when the host has them, LC_ALL=C, the host's own NO_COLOR and FORCE_COLOR, then the names pass_env lists, then the values env gives, all fixed when the handle is made, never per call. pass_env: 'all' is the hatch that hands over the host's whole environment, as strong as -A, so use it only where a person chose it, and review it as such. omit_env beside it leaves out exact names, case-sensitive and never a glob.

start is a long-lived SpawnChild, timeout_ms and signal end a call's child (SIGTERM, then SIGKILL after a grace period), and a call ended that way resolves to a result of kind timed_out or aborted, never a rejection. A child with no inherited stdio is the leader of its own process group, in a new session, so a stop, the cap, and the drain bound reach what it left behind. A child with an inherited stream stays in the terminal's session and foreground group, since a new session would lose the terminal: /dev/tty prompts and Ctrl-C reaching it. Such a child is stopped by pid alone. After the direct child exits, a call waits a bounded time for its pipes to close, then kills the group and stops reading, so a background grandchild holding a pipe can't hang it. A reader behind at that bound keeps what's buffered and can still read the rest. A stop's SIGKILL still reaches the group after the leader exits. A background process with its pipes redirected holds nothing the call waits on, so when no stop has begun it outlives the call. A child still running when the host exits is killed, by one hook installed on the first spawn, and while a child in a group of its own runs, the signals that end the host, but for SIGQUIT, kill its group first. A child with an inherited stream is sent a SIGTERM of the host, so a chain of hosts passes it all the way down.

Option objects are read once, each option's value read once into a null-prototype object and checked, so a getter can't change one between its check and its use. Only own properties count as options, so a polluted Object.prototype can't set one on a plain {}.

This is the Node implementation, which runs on the Node Gro. Its gaps against the runtime's builtin, which it documents rather than the API weakening to match:

  • A native binary's pin is a path, resolved then exec'd later by path: a file replaced at that path in between runs in place of what was pinned. The runtime's builtin execs a descriptor. A script is checked by identity, which a file rewritten in place keeps, so it runs as rewritten.
  • program_in resolves beneath its handle by fs's walk, a check then a use, so a symlink swapped in before the pin escapes the handle, as it would an fs op.
  • cwd is read as a path from anything shaped like a handle, its path a checked string, so a forged handle object names any directory. The runtime's builtin takes the handle's descriptor, which only a real handle has.
  • A real cwd handle follows its path too: where fs refuses a directory that was replaced (outside_root, renamed away and a symlink left at the path), a call runs in what the symlink leads to.
  • No policy check, argv limit, or kernel confinement applies to the children: a running program reaches whatever its user can.
  • Piped stdin data reaches the child on a socket, as Node's stdio pipes are socketpairs, so a child reopening it by path, like cat /dev/stdin, fails with ENXIO.
  • A polluted Object.prototype.encoding, highWaterMark, objectMode, or signal makes Node's spawn throw after the fork, so the call rejects launch_failed with the child untracked and running, and with stdin data a child reading its stdin never gets EOF and keeps the host alive.
  • Grouping is Node's detached, which is setsid: a child with no inherited stdio has no controlling terminal, so a program prompting on /dev/tty under out or out_bytes without stdin: 'inherit' can't. A child with an inherited stream isn't grouped, so a stop reaches it by pid alone and anything it left behind survives. Node has no PDEATHSIG, so a SIGKILL of the host leaves every child behind, and a host killed by SIGINT or SIGHUP leaves an inheriting child to what the terminal delivers. Passing SIGINT on would double a terminal's, which makes some programs force-quit, and a listener for SIGHUP would end a nohup host.
  • SIGQUIT isn't hooked, as a listener would keep a host stuck in synchronous code from dumping core, the signal's use, so a SIGQUIT of the host leaves a group running too.
  • Node can't read a signal's disposition, so while a group runs, a SIGHUP a nohup host would ignore reaches the signal hook, kills the group, and ends the host.
  • The signal hook steps aside for any other listener on the signal but another copy of itself, so a library that stands down the same way when it sees another listener (signal-exit) defers to the hook while the hook defers to it, and the signal ends nothing. A once listener prepended after a group started has removed itself before the hook counts it.
  • A group id is signaled after its leader has been reaped, by the drain bound, a stop's grace kill, and the exit and signal hooks, so a kill could in theory reach a group the kernel handed that id to after a full wrap of pids.
  • Intrinsics stay pollutable, as for fs. The module copies at load the Node functions it calls, Array.isArray, Number.isSafeInteger, the process functions, the timers, Buffer.prototype.copy, and Object's assign, create, freeze, keys, and hasOwn, and its own objects are null-prototype, but code that patches Array.prototype, Set.prototype, String.prototype, Promise, Uint8Array, TextDecoder, Error, EventEmitter.prototype.on, or the stream classes after this module loads runs inside these ops, and a patched on or stream method holds the raw ChildProcess or stream.
  • Any module can import node:child_process, so a narrowed spawn bounds only code that uses it, a review signal, not a boundary.
  • The refusal of files with no #! reads only the first bytes, so a file with a native magic the kernel won't load, or a #! line naming no interpreter, still reaches Linux's /bin/sh fallback, and a Java class file passes on macOS, sharing the fat binary's magic.
  • A child killed by a real-time signal is reported as {kind: 'exited', code: 0}, since Node passes an empty signal name for one.
  • Node copies a set NODE_V8_COVERAGE into every child's environment.
  • Importing this module throws in a removed or non-UTF-8 working directory, as fs does.

SpawnCallOptions import type {SpawnCallOptions} from '@fuzdev/gro/spawn.js';

Options for a call that starts a program.

cwd?

The working directory, a handle rather than a path. Defaults to the project root.

type FsReadDir

timeout_ms?

Stops the child this many milliseconds after it starts, SIGTERM then SIGKILL after a grace period. The call's result is then of kind timed_out. A positive safe integer of at most 2147483647.

type number

signal?

Stops the child when it aborts, as timeout_ms does, its result of kind aborted. A signal that had aborted before the call starts nothing: the call throws SpawnError.

type AbortSignal

spawn.ts view source

SpawnOutOptions import type {SpawnOutOptions} from '@fuzdev/gro/spawn.js';

Options for a captured call.

inheritance

extends: SpawnCallOptions

max_bytes?

The most bytes kept of each of stdout and stderr, a non-negative safe integer. Past it the child is killed and the result is truncated. Defaults to 64 MiB.

type number

stdin?

The child's stdin. 'ignore', the default, is /dev/null, and the child leads its own process group, in a new session with no terminal, so a stop and the cap reach what it left behind. 'inherit' shares the host's and keeps the child in the terminal's session, as for any child with an inherited stream, so a command that may prompt (ssh, a credential helper, a pinentry) still reaches /dev/tty. Such a child is stopped and capped by pid alone, so a process it started outlives the call.

A Uint8Array is the data sent to the child's stdin through a pipe, which then closes, empty data closing it at once. It's copied when the option is read, so changing the array afterward changes nothing sent, and written while the output is read, so a child can fill either pipe. Text goes through a TextEncoder, as a string here would collide with the mode names. The child leads its own process group, as for 'ignore'. A child that exits or closes its stdin before reading it all ends the write, which is no error, and the result stands, so a call's result never says whether the data was read.

type "inherit" | "ignore" | Uint8Array<ArrayBufferLike>

Host variables to pass by name, beyond the base set: a name or a PREFIX_* glob. 'all' passes the host's whole environment, as strong as -A. A narrowed root takes names only.
