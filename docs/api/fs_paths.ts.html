fs_paths.ts

Gro's boundary from paths that arrive from outside to the fs host module's handles.

A path from a CLI arg, a config, or one of Gro's well-known paths names a file by absolute or project-relative path, while a handle takes only relative paths beneath it. An FsPaths converts one into the other where the path enters code that reaches the filesystem. It follows symlinks the way fs.open_dir does, the same inside and outside the project, so the confinement of a handle applies only to the paths code resolves beneath a handle it already holds.

It opens any path, so it's built from the root Fs and never from a handle: a composition root that imports the host module builds one with create_fs_paths(fs) and passes it down, and code given one reaches what the root's fs reaches. Code that holds a handle gets narrower handles from it, never wider ones by path.

FsPaths
#

fs_paths.ts view source

FsPaths import type {FsPaths} from '@fuzdev/gro/fs_paths.js';

Opens paths from outside as handles. A relative path is relative to project, resolved lexically, its .. segments before any symlink is followed, as Node's path.resolve does. Then it's resolved to its real path, every symlink in it followed, a dangling final one to its missing target, and a missing part appended to its nearest existing ancestor's real path. A real path at or beneath the project is relative to project; any other opens its parent, or the parent's nearest existing ancestor, with fs.open_dir. So the op on the result follows no symlink but ones created since, and a symlink out of the project, at the end of the path or before it, reaches what it points at.
