'@fuzdev/gro': minor

feat: `test`, `lint`, `typecheck`, and `sync` take their handles from their `host`, their bodies `run_test`, `run_lint`, `run_typecheck`, and `run_sync`; a builtin's program grant, a `BuiltinProgramGrant`, is keyed by role, its tool's name with `_cli` (`eslint_cli`, `svelte_check_cli`, `typescript_cli`, `npm_cli`, `vitest_cli`, `sveltekit_cli`, `git_cli`), with the program's `name`, the only program the role runs, `local` for the project's own install in `node_modules/.bin`, never one on `PATH`, and `pass_env`, `omit_env`, and `env` for its environment; the `stdout` and `stderr` grants give the `host` the root's streams, and every task's `TaskContext` has `implicit_rest_args`, the forwarded section it reads as its own without naming a tool: the CLI's first section after `--` for the task the CLI invoked (none when it starts with `gro`), so `gro test -- --watch` and a project task run as `gro task <path> -- x` read theirs from the context rather than the process's args, and for a task another invokes none unless the invoking task's `invoke_task` passes one in its new `implicit_rest_args` option, as a wrapper forwarding its section to `test` does; every task's `TaskContext` also has `raw_rest_args`, a frozen copy of the CLI args from the first `--` on, the sections a task finds its tools' in with `to_forwarded_argv`

**breaking** A builtin runs only its own tools, so the args and options that chose another program are removed: `gro lint --eslint_cli`, `gro typecheck --svelte_check_cli` and `--typescript_cli`, and `gro changeset --changeset_cli` and `gro publish --changeset_cli` are refused as unknown args; `GroConfig.pm_cli` is removed, npm being the package manager every task runs (the constant `PM_CLI_DEFAULT` is now `NPM_CLI`); `gro_plugin_sveltekit_app` takes no options, its `vite_cli` and the `GroPluginSveltekitAppOptions` type removed; and `gro_plugin_sveltekit_library`'s `svelte_package_cli` and `run_svelte_package`'s `svelte_package_cli` and `pm_cli` are removed. A different tool is a project task that wraps the builtin or replaces it. For oxlint, `src/lib/lint.task.ts` runs it, `const oxlint = find_cli(spawn, 'oxlint', {pass_env: 'all'}); if (!oxlint) throw new TaskError('oxlint is not installed'); if (!spawn_result_is_ok(await spawn_cli(oxlint, [], log))) throw new TaskError('oxlint found some problems');` (`find_cli`, `spawn_cli`, and `spawn_result_is_ok` from `@fuzdev/gro/cli.ts`, `spawn` from `@fuzdev/gro/spawn.ts`), and since `gro check` invokes the builtin `lint`, a project `src/lib/check.task.ts` with the builtin's `Args` runs `await invoke_task('check', {...task_args, 'no-lint': true}); if (task_args.lint) await invoke_task('src/lib/lint.task.ts');`, the scripts and CI running `gro task src/lib/check.task.ts`; the same shape swaps the type checker or the changeset CLI. A `BuiltinProgramGrant` requires `name`, and `host.programs.program` and `find` take the role alone. `GenContext.invoke_task` is removed, so a genfile generates and runs no task: work that invoked a task from a genfile moves to a project task that invokes it and then `gen`. `BuiltinHostRoot` requires `stdout` and `stderr`, `TaskContext` requires `implicit_rest_args` and `raw_rest_args`, so a hand-built context needs both, a `PluginContext` too, `RunTaskOptions` requires it, and `InvokeTaskOptions` and `InvokeTaskContextOptions` take it, `invoke_cli` setting it for the task it invokes. `to_implicit_forwarded_argv(task_name, cli_args, root, command?)` is removed: a task reads its section from its context, and `to_implicit_rest_args(raw_rest_args)` is how a root computes it, none when it starts with `gro`, a task dropping one starting with its own tool's name, as `test` drops `vitest`. `sveltekit_sync(finder)` and `sveltekit_sync_if_obviously_needed(fs_paths, finder)` take a `CliFinder` (`to_cli_finder(spawn, SVELTEKIT_PROGRAM_OPTIONS)` at a root), which finds the CLI only in the project's `node_modules/.bin`, in place of a `Spawn`, and no longer take the CLI's name or the install hint's package manager, `SveltekitSyncOptions` removed. `install_with_cache_healing(programs, options)` and `install_with_cache_healing_or_throw(programs, options)` take an `InstallPrograms` (`to_install_programs(spawn)` at a root), whose `program()` builds npm, in place of a `Spawn` and the package manager's name; `to_install_program_options` is replaced by the data `NPM_CLI_PROGRAM_GRANT`. `to_git_program` takes a `Spawn` with its options, now required, or a builtin's `host.programs` with none, and `GitFinder` is the latter's `find` with the `git_cli` role, which a `Spawn` doesn't fit. `test.task.ts`, `lint.task.ts`, `typecheck.task.ts`, and `sync.task.ts` export `task` as a `BuiltinTask`, so run them by name or call their bodies with plain objects; by path they're refused. Importing `test.task.ts` or `typecheck.task.ts` no longer reads the working directory in its own module scope, their `dir` and `cwd` defaults made when the args are parsed.
