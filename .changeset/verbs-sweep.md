'@fuzdev/gro': minor
---

**breaking** feat: relative and absolute imports resolve to exactly the file they name in the loader, the Filer's import graph, and server builds, with no extensionless probing and no `.js`-to-`.ts` mapping (`./foo.ts`, not `./foo` or `./foo.js`); a `.js` specifier with a `.ts` sibling now loads the `.js`; in the loader and server builds an unresolvable import fails with the specifier, the importer, and the fix (the Filer records the edge to the named path so a file created later links), and a `#lib/x.js` naming a `.ts` file gets the fix appended to Node's error; `#lib/*` and other subpath imports resolve only through Node, with no `.js`-to-`.ts` retry; `resolve_specifier` takes the importer's path instead of its directory and throws for a specifier naming no file; `to_missing_module_id` is removed and `to_specifier_path_id` added

**breaking** feat: `esbuild_plugin_external_worker` is removed, and server builds no longer build a `.worker.ts` or `.worker.js` import separately and externalize it, so it gets no special handling; `ResolvedSpecifier.mapped_specifier`, which only that plugin read, is removed

**breaking** feat: `TaskContext` and `PluginContext` replace `filer` with `graph` (a `ModuleGraph`: `modules`, transitive `dependents`, content-based change events through `watch`, and `close`) and `watcher` (a `Watcher`: a plain file watch reporting changes from when it starts), both always present and loaded on first use, so a task that never uses them no longer loads the Filer, chokidar, or the import parser; the interfaces are types only in `module_graph.ts`, with the Node implementations `create_node_module_graph` and `create_node_watcher` in `module_graph_node.ts`; `GenContext` and `GenContextBase` lose `filer`; `GroConfig.filer_options` is replaced by `watch: {dir, filter}` (default `src/` and no filter); `invoke_task` and `run_task` take their trailing params as one options object, `invoke_task(task_name, args, {config, watching, timings, parent_log})` (`InvokeTaskOptions`, with `watching` as `{graph, watcher}` in place of a `Filer`) and `run_task(task_meta, args, {invoke_task, config, graph, watcher, log, timings})` (`RunTaskOptions`, `graph` and `watcher` in place of `filer`), and a task's `invoke_task` takes `{config}` (`InvokeTaskContextOptions`) in place of its positional `config`; `run_gen` drops its `filer` param, and `should_trigger_gen` takes a `ModuleGraph`; the server plugin watches with its own `watcher` instead of the graph, so it no longer rebuilds once per existing file at startup, and a save that leaves a file's contents unchanged now rebuilds and restarts the server; `FilerOptions.package_json_cache`, which nothing read, is removed

**breaking** feat: `GenConfig.dependencies` is replaced by static `inputs`, `'all'` or `{files, patterns}`, plain data the gen plugin reads from the genfile's `gen` export, and a leftover `dependencies` key is ignored: `patterns` are gitignore-syntax strings anchored at the project root like a root `.gitignore` (`*.json` at any depth, `/package.json` at the root, `!` to exclude), matched by tsv's `IgnoreStack` and only for files inside the root, replacing `RegExp`s tested against absolute paths; `files` are exact paths, relative to the project root or absolute; the resolver function form, `GenDependenciesResolver`, and `GenContext.changed_file_id` are removed, `GenDependencies` becomes `GenInputs`, `GenDependenciesConfig` is removed with its shape inlined in `GenInputs`, and `create_gen_context` drops its third param; `should_trigger_gen` takes `(gen_file_id, changed_file_id, graph, log)`, returns true for the genfile's own changes and its imports' before importing it, and no longer busts the module cache, so an edit to a genfile's `inputs` applies when `gro dev` restarts; `gen_inputs_match` is added; `gen_task_registry` and Gro's own genfiles declare gitignore patterns

**breaking** feat: the Filer family leaves the public exports: `filer.ts`, `disknode.ts`, `watch_dir.ts`, and `parse_imports.ts` move under `internal/`, which the package exports block with `"./internal/*": null`, so `@fuzdev/gro/filer.ts` and the others no longer resolve; use the `graph` and `watcher` on the task and plugin contexts, or `module_graph_node.ts`

**breaking** feat: a name means only a builtin and project tasks run by path: `gro task <path>` runs a task file, its path relative to the cwd (the project root) or absolute, `./` optional, the `.task.ts` or `.task.js` suffix required (`gro task src/lib/foo.task.ts`, not `gro foo`); `gro <name>` runs only the builtin of that name, so a project task never shadows a builtin and builtin-to-builtin calls like `check` to `format` always reach the builtin; an unknown name errors with "No builtin `foo`", the builtin list, and the hint `gro task src/lib/foo.task.ts`, saying whether that file exists; a path without `gro task` (`gro src/lib/foo.task.ts`, `gro some/dir`) errors with the `gro task` form; the `gro/` prefix is removed, and `gro gro/x` errors naming the plain builtin `x`; `invoke_task` takes a builtin name or a task path by the same rule and base, with no search; listing is explicit: `gro` prints the builtins and usage from generated summaries, importing no task module, `gro task` lists the project's tasks under `src/`, and `gro task some/dir/` lists that directory; tasks are displayed and keyed by their builtin name or normalized root-relative path, so forwarded args reach a project task as `gro check -- gro task src/lib/foo.task.ts --a`

**breaking** feat: task resolution's search is removed: `GroConfig.task_root_dirs` is removed with no replacement, as are the `resolve` task, `find_tasks`, `load_tasks` (now `load_task(id, name)`), `to_task_name`, `FoundTask`, `FoundTasks`, `FindTasksResult`, `FindModulesFailure`, `LoadedTasks`, `LoadTasksResult`, `LoadTasksFailure`, `GRO_PACKAGE_DIR`, and `GRO_DIST_DIR` (with `print_path`'s `gro` label for it); `load_module` drops its `bust_cache` param; `to_input_path` no longer maps a `gro/` prefix and `get_possible_paths` no longer special-cases Gro's dist; `TaskRegistry` is `GroBuiltinTasks & ProjectTasks`, with no `gro/` keys and no shadowing, and `gen_task_registry` keys `ProjectTasks` by each task's root-relative path under `src/` (`'src/lib/foo.task.ts'`); `InvokeTask` accepts a literal task path not in the registry with loose `Args` and refuses a literal name that's no builtin; `task_registry_find` takes `(dir, search_filters, root)` and names entries by path; `GRO_BUILTIN_TASK_SUMMARIES` is generated beside `GroBuiltinTasks`; `to_task_args` returns `{task_name, task_path, args}` with `task_name` `'task'` for the verb; `invoke_cli` is added for the CLI's forms, with `resolve_task`, `is_task_path_input`, `to_task_path`, `to_task_command`, `is_builtin_task_name`, and `to_builtin_task_id`; `log_tasks` takes `(log, modules, dir_label)` and `log_builtin_tasks` is added; `task_registry_render_builtins` takes `BuiltinTaskEntry` (with `summary`), found by the new `task_registry_find_builtins`; `invoke_task`'s first parameter is a `string` task name or path; `InvokeTask` strips a leading `./` from a literal path before checking its args against the registry; `TASK_VERB`, `CliTaskArgs`, `TaskPathLiteral`, `TaskPathNormalized`, `ResolveTaskResult`, and `LoadTaskResult` are added

**breaking** feat: `search_filters` test each path relative to the project root, not its absolute id, whichever directory a search starts in (a path outside the root keeps its absolute id), through the new `to_search_filters_relative` in `paths.ts`, for gen, task listing, `gen_task_registry`, and `gro format`, including its glob patterns; `find_genfiles` and `format_directory` take an optional `root` param, defaulting to `paths.root`; `SEARCH_EXCLUDER_DEFAULT` drops its carve-outs for Gro's `dist/` (`gro/dist`, `node_modules/@*/gro/dist`), excluding every `node_modules/` and `dist/`

fix: the module graph no longer fails to load on an import naming a directory (`import '../../'`), which rejected with `EISDIR` and left unhandled rejections; the directory, or a path through a file (`ENOTDIR`), is a contentless node like a missing file

fix: the module graph no longer records the raw source text of a dynamic import of a template literal with a substitution or a string concatenation (`` `./locales/${lang}.ts` ``, `'./x' + 'y'`) as a dependency, and static import specifiers are read decoded, so escapes resolve exactly

fix: a flag that replaces the positional args, like `gro run --no-_` or `gro test --_`, is a usage error instead of a crash on `args._.shift is not a function`, in the CLI's args and in forwarded `gro` sections

fix: a project under a `.`-prefixed directory, like a checkout in `~/.cache/` or `.claude/worktrees/`, finds its genfiles, tasks, and files to format, where the default `search_filters` excluded every path and `gro gen --check` passed with nothing checked

fix: a malformed forwarded `gro` command, like `gro check -- gro` or `-- gro task` with no path, is a usage error instead of an unhandled one

fix: `is_gen_path` tests the file name only, so a project under a directory like `my.gen.x/` no longer treats every file as a genfile

**breaking** fix: a task that fails is reported once: `invoke_task` logs its error (with the stack for an unexpected one) and rejects with a `SilentError` with the original error as its `cause`, where it rejected with the original, so an invoking task says only that it failed and the CLI prints no duplicate error and stack; a task's invalid args fail the same way, with the failure line under the task, where `run_task` threw a `TaskError` (it now returns `{ok: false}` with the `TaskError` as `error`)

**breaking** fix: args forwarded to outside tools pass verbatim, where parsing and reserializing them dropped `--no-cache`, reordered `--max-warnings -1`, split `--grep -foo` into `-f -o`, and rewrote `0123`, `1.10`, `1e3`, and `--x=`: `eslint`, `svelte-check`, `tsc`, `vite`, `svelte-package`, the package manager in `gro upgrade`, and `vitest` get their section's text as written, and only `-- gro <task>` sections are parsed; empty-string args are forwarded as-is; a task's own flag (`lint`'s `--max-warnings 0`, `tsc`'s `--noEmit`, matched case-insensitively, and configured `svelte-package` options by spelling) is dropped when the forwarded text names it as `--x`, `--x=…`, or `--no-x`, with the forwarded text after Gro's args (`--noEmit` after it, so `tsc --build` stays first), a configured `svelte-package` option of `false` passes as `--no-x` (`w` and `t` as `--no-watch` and `--no-types`) where it was dropped, and a forwarded `-- svelte-package --output x` also sets the directory the library plugin rewrites imports in; an `-- eslint` section's positionals add to `lint`'s paths where they replaced them; `gro run <path> ...rest` passes everything after the path to the script verbatim, including `--help` and any `--`, so `gro run x.ts -- --help` now passes the `--` too, and a flag before the path other than `--help` is a usage error saying to put it after the path (`invoke_task('run', args)` still serializes its named args); implicit forwarding (`gro test -- --watch`) reads only the first section and only for the task the CLI invoked, so `gro check -- --watch` and `gro check -- gro test --coverage` give `vitest` nothing implicit, while a `-- vitest` section reaches it at any depth; a forwarded `-- gro <path>` or `-- gro gro/x` errors with the CLI's hint instead of being ignored; a literal `--` still can't be forwarded except to `gro run`'s script; `to_implicit_forwarded_args` and `to_forwarded_args`' `cache` param are removed, `to_forwarded_args` and `to_forwarded_args_by_command` cover only `gro` sections, and `to_forwarded_argv`, `to_implicit_forwarded_argv`, `has_forwarded_flag`, and `to_forwarded_flag_value` are added

fix: a task whose nested `invoke_task` fails, like one invoking a name that's no builtin, reports that it failed instead of an unexpected error suggesting `npm install` and `gro clean`

fix: a failed `svelte-package` fails the library plugin with a `TaskError`, where its exit was ignored and the plugin went on to rewrite imports in a stale output directory

fix: a server build compiles a Svelte runes module imported by a relative path, like `./state.svelte.ts`, where its own imports failed to resolve (`Could not resolve "svelte/internal/server"`)

fix: the loader and server builds compile Svelte runes in any module with `.svelte.` in its file name followed by `.js` or `.ts`, like `state.svelte.test.ts`, vite-plugin-svelte's default rule, where `SVELTE_RUNES_MATCHER` matched only a `.svelte.js` or `.svelte.ts` suffix

fix: an import specifier starting with `//` (`//home/x/a.ts`) is refused naming the fix, a single `/`, where the loader and server builds loaded `/home/x/a.ts` and Node refuses it as a URL host

fix: `gro publish` fails with a `TaskError` when its release `git commit` or final `git push --follow-tags` fails, saying the version is already published to the registry and naming the manual recovery, where it reported success

fix: the top-level task prints its timings and total time on success, which no task printed while every nested `invoke_task` printed the shared ones, and a task that fails still closes the module graph and watcher its `invoke_task` created

fix: the module graph records `export * from` and `export * as ns from` re-exports, and dynamic imports anywhere in a module are read decoded from the parser, so an escaped quote no longer drops one
