**breaking** feat: relative and absolute imports resolve to exactly the file they name in the loader, the Filer's import graph, and server builds, with no extensionless probing and no `.js`-to-`.ts` mapping (`./foo.ts`, not `./foo` or `./foo.js`); a `.js` specifier with a `.ts` sibling now loads the `.js`; in the loader and server builds an unresolvable import fails with the specifier, the importer, and the fix (the Filer records the edge to the named path so a file created later links), and a `#lib/x.js` naming a `.ts` file gets the fix appended to Node's error; `#lib/*` and other subpath imports resolve only through Node, with no `.js`-to-`.ts` retry; server builds externalize a relative or absolute `.worker.ts` import as its built `.js`; the worker plugin now handles only relative or absolute `.worker.ts`/`.worker.js` specifiers, so an extensionless `.worker` import or a bare `pkg/x.worker.js` gets esbuild's default resolution; `resolve_specifier` takes the importer's path instead of its directory and throws for a specifier naming no file; `to_missing_module_id` is removed and `to_specifier_path_id` added

**breaking** feat: `TaskContext` and `PluginContext` replace `filer` with `graph` (a `ModuleGraph`: `modules`, transitive `dependents`, content-based change events through `watch`, and `close`) and `watcher` (a `Watcher`: a plain file watch reporting changes from when it starts), both always present and loaded on first use, so a task that never uses them no longer loads the Filer, chokidar, or the import parser; the interfaces are types only in `module_graph.ts`, with the Node implementations `create_node_module_graph` and `create_node_watcher` in `module_graph_node.ts`; `GenContext` and `GenContextBase` lose `filer`; `GroConfig.filer_options` is replaced by `watch: {dir, filter}` (default `src/` and no filter); `invoke_task`'s fourth param takes `{graph, watcher}` instead of a `Filer`, `run_task` takes `graph` and `watcher` in place of `filer`, `run_gen` drops its `filer` param, and `should_trigger_gen` takes a `ModuleGraph`; the server plugin watches with its own `watcher` instead of the graph, so it no longer rebuilds once per existing file at startup, and a save that leaves a file's contents unchanged now rebuilds and restarts the server; `FilerOptions.package_json_cache`, which nothing read, is removed
