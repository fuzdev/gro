feat: `format`, `clean`, and `gen` take their handles from their `host`, their bodies `run_format`, `run_clean`, and `run_gen_task` over `FormatDeps`, `CleanDeps`, and `GenTaskDeps`; a builtin that loads the project's modules declares the `project_modules` grant, and its `host` holds the run's project loader as `import_module` and a project task's `invoke_task` as `invoke_project_task`, so `gro gen` loads genfiles through the loader every task loads through and its genfiles invoke tasks as a project task does

**breaking** `format.task.ts`, `clean.task.ts`, and `gen.task.ts` export `task` as a `BuiltinTask`, whose `run` needs the `host`, so call their bodies with plain objects or invoke the builtin with `invoke_task`. `create_builtin_host` takes `(root, grants, invocation)`, the invocation a `BuiltinHostInvocation` of `fs_paths`, `import_module`, `invoke_project_task`, and `raw_rest_args`. `run_gen` takes `(gen_modules, base, root, format_file?)`, `base` the `GenContextBase` every genfile shares, which now includes `load_svelte_config`, called when a genfile reads `svelte_config`, so `gen.ts` no longer loads the Svelte config itself. `discover_dist_dirs` moved from `build_cache.ts` to `clean_fs.ts`. `to_git_program` takes a `GitFinder`, which the spawn host module and a builtin's `host.programs` both are. Each of the three now runs only by its name, so `gro task src/lib/format.task.ts`, `gro task src/lib/clean.task.ts`, or `gro task src/lib/gen.task.ts`, or a project file re-exporting its `task`, fails with a `TaskError` naming the builtin to run instead. Importing `format.task.ts` no longer reads the working directory, as `format` takes its source directory from its `host`'s `fs_paths`; `gen.task.ts` no longer reads it in its own module scope, its `root_dirs` default calling `cwd()` when the args are parsed, though it still imports the grant-free `cwd` host module, whose Node file checks the working directory when it loads.
