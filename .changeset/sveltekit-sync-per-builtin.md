feat: the `svelte-kit sync` Gro ran before every command, for a project declaring `@sveltejs/kit` whose `.svelte-kit` or `node_modules/$app/tsconfig.json` was missing, now runs only in the builtins that read SvelteKit's generated files, each through its own `sveltekit_cli` program grant: `gen` and `lint` first, and `check` before its `build` step, whose `svelte-package` reads them, which nothing in `check` has synced by then; `typecheck` still runs a full sync, as `dev`, `build`, and `sync` do, and `test`'s Vite syncs when it starts. When `svelte-kit` isn't installed, each builtin that syncs warns once, under its own label, that SvelteKit's files weren't synced, so `check` running `gen` and `lint` warns from each. On an unsynced project the listing, `--version`, a usage error, `format`, `clean`, `run`, `task`, and project tasks no longer sync, and no longer fail when the sync can't run. `run_gen_task`'s `GenTaskDeps` requires `programs`, as do `run_lint`'s and `run_check`'s, holding `sveltekit_cli`.
