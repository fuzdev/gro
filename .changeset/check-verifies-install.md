feat: `gro check` verifies the install and `package.json` and writes neither. It no longer runs `gro sync` first, which wrote `package.json`'s exports and ran a second full `svelte-kit sync`, so its `package.json` check now fails a drifted file naming `gro sync` where it passed after rewriting it, and a forwarded `-- gro sync …` section is ignored unless `--install`. A new step checks the npm install against `package.json` and `package-lock.json` with `npm_install_check` (`@fuzdev/gro/npm_install_check.ts`), reading only those, npm's hidden lockfile `node_modules/.package-lock.json`, and the installed packages' `package.json` files, no npm run: `package.json`'s dependency specs against the lockfile's root entry, each locked package's `version`, `resolved`, `integrity`, and `link` against the hidden lockfile with packages installed but not locked, and each installed package's version, an optional or platform-limited package allowed to be absent, as is the hidden lockfile when nothing is locked to install. A mismatch fails with "the install doesn't match package.json and package-lock.json: run `npm i`, or pass `--no-lockfile` to skip this check", naming at most ten. With no `package-lock.json` it says at info level that the install wasn't checked, and the same when `node_modules` is itself a symlink, which isn't followed, like a worktree sharing a checkout's install; a package installed as a symlink, or beneath a scope directory linked from outside the project, is skipped with an info note. It's a review signal against mistakes like pulling without installing, not a boundary. `gro check --install` still installs first, through `gro sync --install --no-gen --no-package_json`, so it writes no `package.json` either, and `check`'s grants invoke `sync` only `{when: 'install'}`.

**breaking** `gro check`'s `sync` and `no-sync` args are removed, as it syncs nothing but under `--install`; `--no-lockfile` skips the new install check. `NPM_HIDDEN_LOCKFILE_PATH` moved from `build_cache_dependencies.ts` to `constants.ts`.
